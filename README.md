# 万物声谱｜乡村儿童声音创作教学智能体

万物声谱面向乡村小学低年级儿童：孩子不需要拥有电子设备，也不需要学习复杂的音乐软件，只需用纸笔记录听见的声音、画出变化并完成圈选；老师使用一部手机协助录入。系统把儿童采集的现实声音转译为可编排的声音单元，在保留原声来源和儿童选择的前提下生成短曲，并给出儿童能理解、能够继续尝试的音乐发现。

当前仓库是可运行的比赛版本，不是纯静态页面，也不把所有结果伪装成联网 AI。基础作品由确定性规则和浏览器音频引擎完成；联网模型用于作品理解、智能音符背景和可选音乐背景。模型不可用时，系统会明确提示并使用本地动态方案，儿童原声和作品保存不受影响。

## 目标场景

- **目标用户**：乡村小学低年级儿童及开展美育活动的老师。
- **现实限制**：无法保证每名儿童都有设备；儿童不会复杂数字操作；音乐教师与专业编曲工具难以稳定覆盖。
- **产品原则**：纸笔优先、老师协助、儿童决定；AI 在后台降低创作门槛，不增加儿童操作负担。

## 完整任务闭环

1. 儿童在纸质声卡上记录声音来源及高低、长短、变化、轻响、出现方式等选择。
2. 老师拍摄或上传声卡，在页面中确认结构化信息并绑定系统声音、历史声音或现场录音。
3. 系统保留不可覆盖的原始音频，根据六项选择生成非破坏性的声音单元。
4. 儿童选择声音，在“万物声场”调整声音的前后、高低、重复与情绪。
5. 系统检查作品时长、声音数量、高低分布、疏密和重叠，保留儿童已有编排并补齐必要位置。
6. 进入成曲前自动尝试 Fun-Music；失败时由用户选择重试、千问智能音符方案或只听儿童声音。千问失败后仍可使用本地动态背景。
7. 儿童对比有无背景的作品；AI 背景始终独立、低增益、可关闭，不能覆盖儿童原声。
8. 作品保存到本机，刷新后可恢复项目、声音、进度和累计归档；归档中可播放、查看组成声音、追溯来源，并获得一条音乐发现与下一次尝试建议。

## AI 与规则的职责边界

| 能力 | 实现方式 | 失败处理 |
|---|---|---|
| 纸质声卡读取 | 当前按定制声卡固定区域读取并由老师确认；已预留识别服务接口 | 保留人工确认，不让模型替儿童决定 |
| 基础声音转译与编排 | 结构化六字段 + 确定性规则 | 基础作品不依赖联网模型 |
| 作品理解与音乐启发 | OpenAI-compatible 文本模型，当前部署可配置千问 | 返回不合格或超时时使用本地教学规则 |
| 智能音符 Plan B | 文本模型生成受约束的音符 JSON，浏览器合成音频 | 校验失败后使用本地动态音符方案 |
| 音乐背景 | 阿里云百炼 Fun-Music 通道 | 失败后明确提示，由用户选择 Plan B 或纯儿童原声 |
| 归档与恢复 | 浏览器 IndexedDB（Dexie） | 存储不可用时提供内存降级并显示状态 |

这不是让大模型任意控制全流程的自主 Agent。项目采用“状态驱动工作流 + 确定性工具 + 可选模型”的架构：规则保障低龄儿童操作稳定、原声安全和结果可复现；模型只承担需要理解与生成的环节。

## 数据与安全

- API Key 仅保存在服务端环境变量中，不进入浏览器代码或 Git 仓库。
- 作品理解接口只接收匿名的音乐结构摘要，不接收儿童姓名、照片、录音文件或地点。
- 原始录音不可覆盖；处理参数与原声分开保存。
- AI 生成背景与儿童原声分轨播放，可关闭、可拒绝，生成失败不阻塞保存。
- 联网接口设置单访客限频、并发限制和单实例每日限额；这些限制是演示保护，不等同于生产级全局配额系统。
- 产品提供教学辅助和音乐启发，不替代教师的教学判断或对儿童的正式评价。

## 本地运行

运行环境：Node.js 22.13 或更高版本。

```bash
npm install
cp .env.example .env.local
npm run dev
```

不配置联网模型时，基础作品、声音编排、播放、保存、恢复和本地教学建议仍可运行。

## 模型配置

所有变量均为服务端配置，示例位置见 [`.env.example`](.env.example)。

- `COMPOSITION_ADVISOR_*`：作品理解与智能音符方案，共用 OpenAI-compatible 接口。
- `FUN_MUSIC_*`：Fun-Music 音乐背景通道。
- `SOUND_CARD_RECOGNITION_*`：预留的声卡识别接口；当前固定模板流程不依赖该接口。
- `*_ALLOWED_USER_ID`：可选。公开短期评审可以留空，但应保留限频；受控演示可填写指定用户 ID。
