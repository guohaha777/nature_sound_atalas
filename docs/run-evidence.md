## 2. 已验证的完整成功链路

项目方已在公开版本完成以下人工走查：

1. 从首页开始新的声音创作；
2. 上传/拍摄纸质声卡并录入三条声音；
3. 确认声卡、绑定系统声音/历史声音或现场录音；
4. 试听声音生命体并选择进入作品的声音；
5. 在万物声场调整事件位置、高低、重复、情绪和15/30秒时长；
6. 自动尝试音乐模型；
7. 音乐模型失败时选择千问智能音符 Plan B，并生成与作品结构相关的动态背景；
8. 对比有背景/无背景作品，保存并进入归档；
9. 在归档中播放作品、查看组成声音与来源、阅读音乐发现和下一次尝试；
10. 刷新页面后恢复项目、声音、作品和进度。

人工走查结论由项目方提供；自动化验证结果见下方本机实际运行记录。

## 3. 异常与降级链路

- Fun-Music 未配置、403、超时或无有效音频：显示真实失败原因，不直接伪装成功。
- 用户可选择重试、使用千问智能音符方案或只听儿童声音。
- 千问音符结果超时、JSON无效、时长或节拍不一致：拒绝结果并使用本地动态方案。
- 作品理解不可用或结果缺少音乐创作价值：使用本地教学规则。
- 浏览器持久化不可用：切换内存存储并在界面显示状态。
- 背景不影响儿童原声保存，基础作品不依赖联网模型。

## 5. 评委建议验证路径

- **主链路**：使用示例声卡与声音库，在5分钟内完成一首15秒作品并归档。
- **个性化证据**：更改情绪、声音高低/轻响或事件位置，再生成一次，比较背景与音乐发现是否变化。
- **失败证据**：关闭或移除音乐模型配置，确认界面出现Plan B选择且仍能完成作品。
- **可追溯证据**：在归档中查看组成声音和来源，并刷新页面确认恢复。
