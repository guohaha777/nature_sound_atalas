# 技术说明｜万物声谱

## 1. 技术选择

万物声谱采用“状态驱动教学工作流 + 确定性声音工具 + 可选生成模型”的混合架构。低年级儿童需要稳定、可预测且步骤少的体验，因此基础作品不依赖联网模型；模型只进入需要理解作品和生成背景的环节。

## 2. 输入、状态与输出

- **输入**：纸质声卡、现场录音或声音库、六项儿童选择、声音编排、全曲情绪和15/30秒时长。
- **上下文状态**：项目、纸卡、确认声卡、不可变原声、声音单元、作品事件、模型结果、归档与进度。
- **输出**：可播放短曲、可关闭的独立背景层、来源可回溯的作品归档、儿童能理解的音乐发现和下一次操作建议。

## 3. 工作流与工具

| 阶段 | 主要工具 | 关键约束 |
|---|---|---|
| 声卡录入 | 固定模板读取、教师确认、录音/声音库绑定 | 不在信息确定时增加额外确认；原声来源必须可追溯 |
| 声音转译 | 六字段音乐映射、非破坏性处理 | 不覆盖原始音频，单次录音上限15秒 |
| 声场编排 | 状态协调器、确定性编排器 | 保留儿童摆放，只为新增声音补位置 |
| 作品理解 | 匿名结构摘要、千问兼容接口、结果结构校验 | 不传儿童身份和原始录音；不合格结果拒绝使用 |
| 背景生成 | Fun-Music；千问音符 Plan B；本地动态音符 | 先尝试音乐模型，失败后由用户选择；背景不能压住原声 |
| 播放与归档 | Tone.js 双总线、Dexie/IndexedDB | 作品时长严格对应15/30秒；原始素材完整保留；刷新恢复 |

## 4. Agent能力边界

当前运行版本通过作品状态和工具结果决定下一步，并具备模型失败、结果校验、人工选择和本地降级分支。代码中同时提供教学 Agent 的状态、决策、工具端口与执行记录模块；其中状态协调、模型选择和失败分支已接入真实产品，完整决策轨迹尚未全部展示或持久化。因此参赛材料将其表述为“状态驱动的声音创作教学智能体”，不宣称为完全自主规划型 Agent。

## 5. 模型与接口

- **作品理解/教学建议**：OpenAI-compatible Chat Completions 接口，模型由 `COMPOSITION_ADVISOR_MODEL` 配置；当前可使用千问系列。
- **智能音符方案**：同一文本模型根据作品时长、节拍、情绪、音高分布、疏密和儿童声音角色输出受约束 JSON，再由浏览器合成。
- **音乐背景**：阿里云百炼 Fun-Music 通道，独立生成无歌词、无人声、弱主旋律背景。
- **声卡视觉识别**：已预留接口，当前比赛版本使用量身定制纸卡的固定区域录入和教师确认，避免为展示 AI 增加冗余操作。

## 6. 工程实现

- Next.js 16、React 19、TypeScript、Zod；
- Tone.js 负责原声与背景分轨播放；
- Dexie/IndexedDB 保存项目、声音、作品与进度；
- API 路由保护服务端密钥并校验第三方返回；
- 同时支持标准 Next.js 和 Sites/Cloudflare 构建；
- Vitest、类型检查、双构建和渲染检查覆盖核心规则与部署路径。

## 7. 可复用部分

纸质声卡六字段规范、声音映射规则、作品结构摘要、模型输出约束、背景安全策略、失败降级链路和存储端口均可独立替换或迁移到其他低设备教育活动。
